# 部署与运行说明

## 1. 前置条件

目标环境为 Ubuntu 22.04、ROS 2 Humble 和 Jetson Orin。请先按厂商文档安装 JetPack、ZED SDK、`zed_wrapper`，并确认相机能够独立启动。ROS 依赖包括 Nav2、RTAB-Map、tf2 和 rosbridge_server。

震动马达不能由 GPIO 直接大电流驱动，应使用适合的三极管或 MOSFET 驱动、续流保护及共地设计。上电前确认 BOARD 编号 7、29、31 与实际接线一致。

## 2. 系统依赖

```bash
sudo apt update
sudo apt install -y python3-pip python3-venv portaudio19-dev alsa-utils \
  ros-humble-navigation2 ros-humble-nav2-bringup \
  ros-humble-rosbridge-server ros-humble-rtabmap-ros
```

ZED 相关 ROS 包通常由 ZED 官方工作空间提供，不同 JetPack 版本的安装方式可能不同。

## 3. 构建

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone YOUR_REPOSITORY_URL Blind-Navigation-System
cd Blind-Navigation-System
python3 -m pip install -r requirements.txt

cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select blind_navigation_system
source install/setup.bash
```

如果使用 Python 虚拟环境，应以 `--system-site-packages` 创建，否则虚拟环境可能看不到 ROS 2 的 Python 包。

## 4. 配置

1. 将 RTAB-Map 定位数据库复制为 `~/.ros/rtabmap.db`，或启动时传入 `database_path:=/绝对路径/rtabmap.db`。
2. 在 `config/navigation.yaml` 中设置两个目标点及导航阈值。
3. 如使用静态二维地图，保证 YAML 中的 `image` 使用相对路径并与 PGM 文件同目录。
4. 通过环境变量配置模型：

```bash
export DASHSCOPE_API_KEY='你的密钥'
export AUDIO_INPUT_DEVICE=pulse
```

`.env.example` 是变量清单，不应把真实密钥写入并提交。

## 5. 主机网络缓冲区

高频点云可能需要更大的接收和发送缓冲区。启动文件不会执行 `sudo`。如现场验证确有丢包，可由管理员在系统层配置：

```bash
sudo sysctl -w net.core.rmem_max=8388608
sudo sysctl -w net.core.wmem_max=8388608
```

长期配置应写入受运维管理的 `/etc/sysctl.d/` 文件，而不是写进应用代码。

## 6. 启动

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
export DASHSCOPE_API_KEY='你的密钥'
ros2 launch blind_navigation_system blind_guide.launch.py
```

常用覆盖参数：

```bash
# 不启动感知模块
ros2 launch blind_navigation_system blind_guide.launch.py enable_perception:=false

# 指定定位数据库和 Nav2 参数
ros2 launch blind_navigation_system blind_guide.launch.py \
  database_path:=/data/maps/site-a.db \
  params_file:=/data/config/nav2-site-a.yaml
```

启动时序为：相机/TF/rosbridge 立即启动，RTAB-Map 在 10 秒后启动，Nav2 在 25 秒后启动，导航和感知进程分别在 40 秒、45 秒后启动。

## 7. 验证清单

```bash
ros2 node list
ros2 topic hz /zed/zed_node/odom
ros2 topic hz /zed/zed_node/point_cloud/cloud_registered
ros2 topic echo /local_costmap/costmap_raw --once
ros2 run tf2_ros tf2_echo map base_link
```

现场测试应依次验证：停止按钮或命令、三路马达方向、目标点位置、偏航重规划、静态障碍、移动障碍、语音打断、断网降级和进程退出后的 GPIO 状态。

## 8. 日志与故障排查

ROS 2 日志默认位于 `~/.ros/log/`，也可直接观察启动终端。

- 没有图像：检查 rosbridge 9090 端口和压缩图像话题；
- 没有声音：用 `arecord -L`、`aplay -L` 检查设备，调整 `AUDIO_INPUT_DEVICE`；
- 没有马达：检查 `Jetson.GPIO`、BOARD 引脚和进程权限；
- 无法规划：检查 `map -> odom -> base_link` TF、目标点是否在可通行区域、Nav2 生命周期；
- 感知无法连接：确认 `DASHSCOPE_API_KEY`、系统时间和网络；
- 点云丢包：降低帧率/点云频率后再评估网络缓冲区。

## 9. 停止与恢复

按 `Ctrl+C` 退出启动进程。导航进程会关闭马达并释放 GPIO。若进程被强制终止或设备异常断电，上电前应人工确认马达驱动状态。
