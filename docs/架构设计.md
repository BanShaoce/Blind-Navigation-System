# 架构设计

## 设计目标

重构后的工程将硬件、ROS 2、网络协议和云端模型隔离，避免单个脚本同时承担所有职责。纯计算逻辑不依赖 Jetson 或 ROS，便于在开发机和 CI 中测试；硬件与外部服务通过边界适配器接入。

## 模块职责

### `blind_navigation.common`

- `protocol.py`：定义稳定的 UDP 命令、事件枚举与端口；
- `settings.py`：集中解析环境变量及导航阈值。

### `blind_navigation.navigation`

- `main.py`：创建资源、线程和 ROS 执行器，负责优雅退出；
- `node.py`：导航、偏航检测、临时避障和触觉引导状态机；
- `models.py`：路径采样和线段合并等纯计算逻辑；
- `geometry.py` / `costmap.py`：二维几何与线程安全的局部代价地图查询；
- `command_server.py`：接收本地 UDP 命令并分发给导航节点；
- `motors.py`：封装 Jetson GPIO。非 Jetson 环境自动使用无硬件模式。

### `blind_navigation.perception`

- `app.py`：管理麦克风、扬声器、图像缓存、导航事件和任务生命周期；
- `realtime_client.py`：只负责多模态 WebSocket 协议；
- `intents.py`：将转写文本分类为场景描述、导航命令或普通对话。

## 进程与协议

导航进程监听 `127.0.0.1:5000`，感知进程监听 `127.0.0.1:5001`。当前协议保留原型兼容值：

| 方向 | 值 | 含义 |
| --- | --- | --- |
| 感知 → 导航 | `GO_A` / `GO_B` | 前往座位 / 门口 |
| 感知 → 导航 | `STOP` | 停止导航 |
| 感知 → 导航 | `PAUSE_NAV` / `RESUME_NAV` | 暂停 / 恢复触觉指引 |
| 感知 → 导航 | `MUTE_NAV` / `UNMUTE_NAV` | AI 播报期间屏蔽导航播报 |
| 导航 → 感知 | `ARRIVED`、`BLOCKED` 等 | 触发自然语言播报 |

协议只用于同一设备内的两个进程。若未来需要跨设备控制，应迁移到带身份验证和完整性保护的传输层，不应直接开放这两个 UDP 端口。

## 导航状态

- `IDLE`：没有活动导航；
- `NAVIGATING`：执行路径段跟踪、偏航检查和局部障碍检测；
- `PERCEPTION_ACTIVE`：用户请求场景描述，暂时停止触觉指引；
- 临时避障使用独立标志记录，不改变外部协议。

所有可调阈值位于 `config/navigation.yaml`。目标点由同一文件管理，避免修改 Python 源码。

## 扩展原则

- 新目的地：先扩展协议枚举和配置，再扩展意图映射；
- 新硬件：实现与 `MotorController` 等价的适配器，不在状态机中直接调用厂商 API；
- 新模型供应商：保留 `PerceptionApplication` 的回调语义，替换实时客户端；
- 新纯算法：放入无 ROS 依赖的模块，并先补单元测试；
- 影响人身安全的阈值变更必须在封闭场地回归验证并记录设备、地图和测试结果。
